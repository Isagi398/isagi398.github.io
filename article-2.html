I Stopped Watching Tutorials and Started Building — Here's What Happened

Published: September 6, 2026

When I first started learning web development, I thought I needed to understand everything before I could build something. So I spent a lot of time watching tutorials. I would learn a little HTML, then some CSS, then watch another tutorial. I understood individual things, but when I opened a blank file and tried to build something myself, I got stuck. I didn't know where to start.

The Problem Wasn't Coding

The biggest problem I had was not that I couldn't write code. It was that I didn't know What to build or how to begin.

When a tutorial gives you instructions, everything is already decided:

  • what you're building
  • what files you need
  • what code to write
  • what to do next
    •

    But when you're building something yourself, there is no step-by-step instruction.

    That was confusing for me.

    I realized that I could keep watching tutorials forever, but at some point I had to try building something on my own.

    I Decided to Just Start

    Instead of waiting until I felt ready, I decided to choose a small project. I chose a to-do list. It wasn't an original or complicated idea. I just wanted something simple enough that I could actually finish it. At first, I still didn't know how to build it. So instead of going back to another complete tutorial, I changed the way I searched for help.

    I first started thinking about the individual things I needed.

    For example:

  • How do I add a task?
  • How do I get the text from an input?
  • How do I detect a button click?
    •

    That made the problem feel much smaller.

    I Started Searching for Specific Solutions

    This is the thing that changed everything for me. Previously, I thought in order to get started I had to learn everything first. Instead, I just built something and whenever I got stuck, I tried to solve that specific problem. When it came to JavaScript coding, instead of trying to figure out JavaScript as a whole, all I did was concentrate on one little piece of information at a time. I would try to solve each issue, seeing where this got me. Sometimes it worked and sometimes it didn’t. Sometimes I knew why and sometimes I had to try different things. Why was this so important? Because I was finally learning by doing something!

    Building Felt Very Different From Watching

    From right when I would watch tutorials I started feeling that I knew the coding language. Making something on my own was the best way to find where my knowledge had holes. There were things I was sure I knew how to do until I started using them independently. This was an important realization — you may understand how something works if someone else is showing it to you, but this is very different from doing it yourself.

    the projects made me think.

    What I Learned

    The most important lesson I've learned is that you don’t have to wait until you're prepared to start creating. You could select a small project, begin from what you already know, and learn the unknown bits and pieces throughout the process. For me, this evolved into: Make a choice → Start building → Encounter obstacles → Research the problem → Attempt a solution → Continue building I'm still a novice in website creation, but this technique seems to work a lot better than endless tutorial watching. I continue to use tutorials as needed. Now, I try to make building the focus of my process, and tutorials an instrument rather than the process itself.

    What's Next?

    I will continue to work on side projects and share my learning experience with others along the way. I don’t want to give an impression that I have already mastered the subject. My aim is to learn as much as I can through creation of the projects. This blog is going to be part of the learning journey.
